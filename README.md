# Northwind Support Copilot - Evaluable Core (Week 16)

A thin RAG vertical slice with a full evaluation + observability harness, so
quality is a **measured number**, not a vibe.

```
ingest -> chunk -> embed (text-embedding-3-small) -> Chroma
      -> retrieve top-k -> assemble grounded prompt -> LLM answer with citations
```

Instrumented with **Langfuse** (traces, tokens, latency, cost), evaluated with
**Ragas** (faithfulness, answer relevancy, context precision, context recall),
and gated in CI with **DeepEval** (Tier A).

## Repo layout

```
app/            RAG slice (config, corpus, providers, vectorstore, retrieval, ingest, rag, cli)
  retrieval.py  dense + hybrid (vector + BM25, RRF reranker) retrieval
  tools.py      bounded, validated order-status tool (traced)
  agent.py      router: bounded tool vs grounded RAG
  data/corpus/  synthetic Northwind support docs (generated)
eval/           golden set (jsonl) + Ragas harness + targets + results/
  citation_check.py   citation accuracy (coverage/validity/support/correctness)
  error_analysis.py   5 worst cases tagged retrieval vs generation
experiments/    one-variable experiments + delta report
  llm_judge.py  LLM-as-judge prompt comparison (bonus)
observability/  Langfuse setup notes + before_production.md + screenshots
tests/          DeepEval faithfulness pytest gate (Tier A)
EXEC_MEMO.md    one-page interview-ready memo
```

## Tiers covered

- **Core**: ingest/chunk/embed/retrieve/cited-answer, golden set (32 Q&A across
  easy/ambiguous/multi-hop/adversarial), Ragas scorecard vs Week 15 targets,
  Langfuse tracing, 3+ experiments with measured deltas.
- **Tier B**: adversarial abstention, **citation accuracy** (`make citations`),
  **error-analysis table** of the 5 worst cases tagged retrieval vs generation
  (`make errors`), and a **bounded traced tool/action** (order-status) routed by
  `app/agent.py`.
- **Tier A**: DeepEval CI **faithfulness gate** (`make gate`), latency + cost in
  the scorecard, and a **before-production note** (`observability/before_production.md`).
- **Bonus**: **hybrid retrieval** (vector + BM25 fused with an RRF reranker;
  `--retrieval-mode hybrid`, quantified by `exp4_hybrid`) and an **LLM-as-judge**
  prompt comparison (`make judge`).

## Quick start

```bash
pip install -r requirements.txt
cp .env.example .env          # add OPENAI_API_KEY (+ Langfuse keys)

# One command to reproduce the baseline scorecard:
make reproduce                # = build-corpus + ingest + eval
# or:
./run.sh
```

Ask a single question:

```bash
python -m app.cli ask "How long does standard shipping take?"
```

Run experiments and the CI gate:

```bash
python experiments/run_experiments.py        # includes exp4_hybrid (bonus)
pytest tests/test_faithfulness_gate.py -v
```

Tier B / Bonus extras:

```bash
make analysis                                 # eval -> citation check -> error analysis
make judge                                    # LLM-as-judge prompt comparison
python -m app.cli agent "status of order NW-1001?"   # bounded tool route
python -m app.cli ask --retrieval-mode hybrid "..."  # hybrid retrieval
```

## Offline smoke test (no keys, no network)

The repo ships a deterministic `fake` provider (hashing embedder + extractive
answerer) and an in-memory vector store fallback so you can verify the whole
pipeline runs before spending tokens:

```bash
./run.sh smoke            # or: make smoke
```

> Offline numbers come from a transparent **lexical heuristic** scorer and are
> for plumbing verification only. Submittable metrics require the real OpenAI
> provider + Ragas (`LLM_PROVIDER=openai`).

## What the corpus is

A 20-document synthetic **Northwind Support** knowledge base (shipping, returns,
refunds, payments, accounts, subscriptions, warranty, etc.) generated by
`app/corpus.py`. The golden set references exact doc ids so retrieval can be
scored precisely. Swap in your own Week 15 corpus by dropping markdown files in
`app/data/corpus/` and updating `eval/golden_set.jsonl`.

## Golden eval set

`eval/golden_set.jsonl` - 32 hand-verified Q&A pairs across four flavors:

| Flavor | Count | What it stresses |
|---|---|---|
| easy | 12 | single-doc factual recall |
| ambiguous | 6 | under-specified questions |
| multi-hop | 7 | needs two documents |
| adversarial | 7 | answer not in corpus -> must abstain |

`eval/generate_golden.py` drafts more rows with the Ragas synthetic generator
(hand-verify before merging).

## Metrics & targets

```mermaid
flowchart LR
    A[User] --> B[CLI]
    B --> C[Agent]
    C --> D[Retriever]
    D -->|Hybrid| E[Vectorstore]
    D -->|BM25| F[Lexical Index]
    E --> G[RRF Fusion]
    G --> H[LLM (Groq/OpenAI)]
    H --> I[Answer with Citations]
    I --> J[Langfuse Tracing]
```


| Metric | Asks | Week 15 target | **Measured (ragas)** | Pass/Fail |
|---|---|---|---|---|
| Faithfulness | Does every claim trace to retrieved context? | >= 0.90 | **0.740** | ❌ FAIL |
| Answer relevancy | Does the answer address the question? | >= 0.80 | **0.729** | ❌ FAIL |
| Context precision | Are retrieved chunks relevant & well-ordered? | >= 0.70 | **0.830** | ✅ PASS |
| Context recall | Does retrieved context contain the answer? | >= 0.80 | **0.863** | ✅ PASS |
| Abstention accuracy | Does it say "I don't know" on adversarial rows? | >= 0.90 | **1.000** | ✅ PASS |

The scorecard (`eval/results/baseline_scorecard.md`) prints metric -> score ->
target -> pass/fail, plus Tier A operational readings (avg/p95 latency, cost/query).

## Reflection (filled after real ragas run — 2026-06-18)

**Where did the system fail most - retrieval or generation?**

Retrieval improved significantly: `context_recall = 0.863` and `context_precision = 0.830` both exceed their targets. The bottleneck is now squarely in **generation** — `faithfulness = 0.740` is the weakest metric, meaning the LLM occasionally introduces claims not grounded in the retrieved context. The hybrid (vector + BM25 + RRF) retrieval mode and increased `top_k = 16` clearly helped the retrieval side.

**Did any metric look good while the answer was bad?**

Yes — `answer_relevancy = 0.729` is near the 0.80 target; the answers feel on-topic but some lack strict grounding. This is exactly the pattern warned about: a fluent, relevant-sounding answer that still fails `faithfulness`. The two metrics together act as complementary guardrails.

**Which Week 15 target did you hit, miss, or revise?**

| Metric | Target | Measured | Result |
|---|---|---|---|
| context_precision | 0.70 | **0.830** | ✅ HIT (+0.130 above target) |
| context_recall | 0.80 | **0.863** | ✅ HIT (+0.063 above target) |
| abstention_accuracy | 0.90 | **1.000** | ✅ HIT (perfect) |
| answer_relevancy | 0.80 | **0.729** | ❌ MISS (−0.071) |
| faithfulness | 0.90 | **0.740** | ❌ MISS (−0.160) |

Changes made after seeing baseline (faithfulness 0.686, answer_relevancy 0.229):
- Switched `retrieval_mode` → `hybrid` (vector + BM25 + RRF)
- Increased `top_k` from 4 → 16, `candidate_k` from 10 → 40
- Changed `prompt_variant` → `cot_grounded` (chain-of-thought grounded prompt)
- Added valid Groq API key to enable real LLM provider

These changes raised context metrics above target; faithfulness and relevancy remain work in progress (larger model or stricter prompt constraints are the next levers).
